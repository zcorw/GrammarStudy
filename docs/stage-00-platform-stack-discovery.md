# Stage 0 阶段记录：平台与技术栈发现

## 已确认事实

- 当前项目方向与已有草案一致：文法卡片检索、AI 辅助创建、练习点评
- 首发平台为 `PWA`
- 后端技术栈指定为 `Python + FastAPI`
- 前端技术栈指定为 `React`
- 前端语言为 `TypeScript`
- 数据库为 `PostgreSQL`
- 仓库组织为 `Monorepo`
- 部署方式指定为 `Docker`
- 本轮目标是“易维护的上线版”

## 决策

- 以浏览器端 `PWA` 作为首发终端，不在首版引入原生移动端或小程序并行实现
- 前后端分离方向成立：前端 `React`，后端 `FastAPI`
- 前端默认按 `React + TypeScript` 方向收敛
- 数据持久化默认以 `PostgreSQL` 为主
- 工程组织采用单仓 `Monorepo`
- 交付目标优先考虑上线后的可维护性，而不是最低成本原型或过度前瞻的超大架构
- 部署交付以容器化为默认基线，后续所有模块边界与依赖选择都应兼容 `Docker`

## 假设

- `React` 的具体工程框架尚未锁定，后续可在保持可维护性的前提下在 `Vite`、`Next.js` 等方案中收敛
- 数据库、缓存、对象存储、消息队列等基础设施尚未确认
- Docker 目前表示交付与运行方式，不等于已经确认编排平台或云厂商

## 风险

- 若后续需要 SEO、SSR 或复杂路由预渲染能力，单纯“React”描述还不够，需要在 Stage 5 前锁定具体框架
- 若 AI 能力调用频繁，上线版的成本与延迟会明显受模型、缓存和配额策略影响
- 仅确认 Docker 还不足以指导日志、监控、灰度和备份方案

## 缺失信息

- 项目名称与一句话产品定位
- 目标用户与主要使用场景
- 首版必须上线的功能边界
- 具体部署环境与基础设施选型
- 数据持久化与账号体系方案
