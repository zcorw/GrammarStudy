# Stage 8 阶段记录：测试与交付

## 已确认事实

- 后端重点测试：检索逻辑、创建流程主链路、AI 输出结构校验、入库规则
- 前端重点测试：首页主流程、文法卡片查看与切换、创建流程关键状态、游客与登录用户能力边界
- 测试类型建议：后端 `pytest + API 测试`，前端 `Vitest + 基础组件/状态测试`，E2E 首版补一条主流程即可
- 部署建议：前端静态部署、后端单实例部署、`PostgreSQL` 独立部署、开启 PWA 基础能力
- 首版目标是支持小规模正式运行

## 测试策略

- 优先覆盖主流程，而不是追求测试类型全面铺满
- 后端重点验证检索、创建、入库与 AI 结构输出约束
- 前端重点验证移动端主流程、页面状态切换和权限边界
- E2E 首版只要求一条高价值主链路

## 交付边界

首版交付包括：

- 首页推荐/搜索
- 文法卡片查看
- 相近文法左右滑动切换
- 匿名访问与登录访问
- 文法创建流程
- 选择题练习
- 自由造句 AI 点评
- 最近浏览与游客本地记录

首版暂不交付：

- 管理后台
- 公共库治理
- 复杂推荐算法
- 向量检索
- 支付/订阅
- 社交功能

## 部署基线

- 前端静态部署
- 后端单实例部署
- PostgreSQL 独立部署
- 整体运行环境容器化

## 假设

- 首版运维复杂度以“单实例 + 手工发布可控”为主
- 小规模正式运行阶段可接受较有限的自动化运维能力

## 风险

- 创建即入公共库会让测试难以完全挡住内容质量问题
- 只做一条 E2E 主链路时，回归覆盖面较薄
- 注音转换与 AI 结构化质量仍会成为上线后主要风险源

## 缺失信息

- CI/CD 方案
- 环境划分方式，例如开发、预发、生产
- 发布回滚策略
