# Stage 5 阶段记录：架构与模块边界

## 已确认事实

- 前端为单一移动端 Web 前端，采用轻量 `PWA`
- 前端技术方向为 `React + TypeScript`
- 后端为单体 `FastAPI` 应用
- 数据库为 `PostgreSQL`
- 仓库组织为 `Monorepo`
- 首版不拆后台管理端
- 所有 AI 编排由后端统一处理，前端不直接调用模型

## 架构决策

- 采用“单前端 + 单体后端 + 单数据库”的首版架构，优先可维护性
- 前后端按领域边界分模块，而不是过早拆微服务
- PWA 负责展示、本地草稿与最近记录；后端负责检索、创建流程、权限与 AI 编排
- 登录与匿名访问并存，游客能力与登录用户能力在同一产品内分层实现

## 前端边界

- 单一移动端 Web 前端
- 推荐使用 `React + TypeScript`
- 负责首页、检索结果、文法详情、创建流程、自由造句点评、我的文法等页面
- 负责 PWA 基础能力与本地存储
- 代码结构按 `view / application / domain / infrastructure` 分层

## 后端边界

建议模块：

- `auth`：登录与匿名 session
- `search`：文法检索与候选返回
- `grammar`：文法详情与推荐内容
- `creation`：创建会话、AI 生成、追加提问、完成创建
- `practice`：选择题结果与自由造句点评
- `user`：最近浏览、收藏、学习记录

实现分层：

- `presentation`：FastAPI 路由
- `application`：usecase
- `domain`：领域对象
- `infrastructure`：仓储、配置、持久化

## 数据边界

- `PostgreSQL` 承载正式卡片、用户数据与会话元数据
- 创建流程中的版本历史仅保存在客户端本地
- 正式卡片与创建会话草稿分离建模

## 假设

- 首版以单实例后端部署为基线，后续再按瓶颈拆分
- 管理后台与治理能力后置，不纳入首版模块划分

## 风险

- 单体后端在 AI、检索、用户数据都堆积后，后续模块膨胀风险较高
- 创建版本历史只保存在前端，服务端排障与恢复能力较弱
- 未来引入治理后台时，需要重新梳理内容修改权限边界

## 缺失信息

- React 具体工程框架
- 前端状态管理与数据获取策略
- 日志、监控、告警与备份边界
