# 接口、测试与交付边界

## 一、API 设计约定

- 风格：REST
- 数据格式：JSON
- 鉴权方式：JWT + 匿名 session
- 时间格式：ISO 8601

## 二、接口分组

- `auth`
- `search`
- `grammar`
- `creation`
- `practice`
- `user`

## 三、创建流程接口约定

创建流程按以下顺序设计：

1. 前端先调用检索接口
2. 用户确认需要创建后，再调用 AI 生成接口
3. 创建流程内可调用追加提问接口调整结构化数据
4. 创建完成后，调用“完成创建/入库”接口

## 四、数据建模约定

- 正式卡片有稳定 `id`
- 会话草稿与正式卡片分离建模
- 标签以受控枚举为主，辅以少量自由标签
- 正式卡片与创建会话不要混用

## 五、测试策略

### 后端重点测试

- 检索逻辑
- 创建流程主链路
- AI 输出结构校验
- 入库规则

### 前端重点测试

- 首页主流程
- 文法卡片查看与切换
- 创建流程关键状态
- 游客与登录用户能力边界

### 测试类型建议

- 后端：`pytest + API 测试`
- 前端：`Vitest + 基础组件/状态测试`
- E2E：首版补一条主流程即可

## 六、首版交付范围

- 首页推荐/搜索
- 文法卡片查看
- 相近文法左右滑动切换
- 匿名访问与登录访问
- 文法创建流程
- 选择题练习
- 自由造句 AI 点评
- 最近浏览与游客本地记录

## 七、首版暂不交付

- 管理后台
- 公共库治理
- 复杂推荐算法
- 向量检索
- 支付/订阅
- 社交功能

## 八、部署建议

- 前端静态部署
- 后端单实例部署
- PostgreSQL 独立部署
- 开启 PWA 基础能力
- 先支持小规模正式运行

## 九、当前主要风险

- 创建即入公共库，内容污染风险高
- 公共库允许重复，后续治理压力大
- 注音转换准确率会直接影响检索命中
- AI 质量优先意味着首版调用成本相对更高
